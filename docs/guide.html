Parts

  • Arduino Uno R3 and a USB A–B cable
  • Adafruit 16-channel PWM servo driver (PCA9685)
  • 6× MG996R servos and servo extension cables
  • 5 V 10 A power supply, plus a female barrel-jack adapter to the driver's blue terminal
  • 1000 µF 16 V capacitor
  • 4 male-to-female jumper wires
  • Xbox controller and its USB cable, plus a laptop with Python 3

How it all connects: Wiring.

One-time setup

Arduino

  1. Install the Arduino IDE.
  2. Open Library Manager and install Adafruit PWM Servo Driver Library.
  3. Open firmware/arm/arm.ino, choose board Arduino Uno and its port, and click Upload. Keep the 5 V servo supply unplugged while you upload.

Laptop

cd laptop
python -m pip install -r requirements.txt
python test_arm.py        # should print: all checks passed

First power-on

The servos don't know where they are. On power-up every joint jumps straight to home at full speed. So every time, move the arm by hand to roughly home first, with every joint near the middle of its travel.
  1. Upload the firmware with the 5 V supply unplugged. In Serial Monitor at 115200 baud you should see READY, a LIMITS … line and a POSE … line.
  2. Type hello and press Enter, then P 90 90. Nothing should happen, which shows that bad commands are ignored.
  3. Move the arm by hand to roughly home, then plug in the 5 V supply.
  4. Close Serial Monitor and run python arm.py. Move each joint to its ends, and tighten the limits wherever a joint hits something (see Tuning).
  5. Pull the USB cable while the arm is moving. It should freeze within half a second.
  6. Tune the flip and test it with the real object.

Running it

cd laptop
python arm.py               # auto-finds the Uno, opens the dashboard
python arm.py --port COM5   # if it picks the wrong port
python arm.py --dry-run     # no arm needed: prints the angles it would send
python arm.py --no-browser  # don't open the dashboard tab
  • Close the Arduino Serial Monitor first, because only one program can use the port at a time.
  • Restarting arm.py doesn't move the arm: it asks the Uno where the arm is and carries on from there.
  • Press Ctrl+C in the terminal to quit. The arm holds still.
  • Button layout: Controls.

Debug dashboard

When arm.py starts, it opens http://127.0.0.1:8765/ in your browser. The page updates 10 times a second and shows:

  • Mode: driving, playing (with a progress bar), or recording (with a frame count), plus the exact command just sent to the Uno.
  • Controller: every stick and trigger value and which buttons are held. Use this to check the button mapping.
  • Joints: each joint's angle on a 0–180° bar. The shaded part is its allowed range, the line is home, and the thin bar under it is the stick speed.
  • Log: everything the terminal prints, like saved recordings, stops and errors.

It only runs on your laptop, so nobody else on the network can see it. When arm.py stops, the page shows STOPPED. Run arm.py again and the page reconnects on its own.

Tuning the flip

The angles in laptop/programs/flip.json are placeholders. To set them:

  1. Run python arm.py.
  2. Drive the arm to each position of the flip:
    1. open, over the object
    2. closed on it
    3. lifted
    4. swinging over the top with the claw twisted
    5. lowered behind
    6. released
  3. At each position, press View and copy the printed angles from the terminal or the dashboard log into that step's "pose".
  4. Adjust the "t" times, in seconds from the start. They must keep increasing, or the file is rejected.
  5. Press A to try it. There's no need to restart, because the file is re-read on every press.

If the shoulder sags or buzzes partway through, it can't hold the arm stretched out. Keep the elbow bent as the arm passes over the top.

Troubleshooting

You seeTry
No controller found.Plug the controller in by USB before starting arm.py.
No serial port found.Plug in the Uno's USB cable.
Uno didn't answer with LIMITS/POSEUpload arm.ino, close Serial Monitor, or pass the right --port. Check Device Manager → Ports.
Lost the USB connectionThe cable came out. The arm freezes; plug it back in and re-run.
Servos twitch or jitterCheck the Uno GND → driver GND jumper. Without a shared ground the signal is noisy.
The Uno resets or disconnects when the arm movesServo power must go only to the blue terminal, never the Uno. Check the capacitor is fitted.
A joint hums or buzzes when it's stillIt's pushing against its end stop or holding too much weight. Tighten its limits or narrow its pulse range.
Nothing moves, but the dashboard shows the angles changingThe 5 V supply is off, or the driver's SDA/SCL jumpers are swapped.

Servo specs (MG996R)

Typical values. Clones vary, so trust what your servos actually do.

SpecValue
RotationAbout 180°. It holds an angle rather than spinning
Pulse width500–2500 µs for 0–180° (some units 1000–2000 µs). 1500 µs = 90°
Voltage4.8–6.6 V (5 V supply = the weaker end)
TorqueAbout 9.4 kg·cm at 4.8 V
Stall currentAbout 2.5 A at 6 V, per servo

Shoulder check: take the weight of everything past the shoulder, in kg, and multiply it by how far out that weight sits, in cm, with the arm stretched straight. Keep the result under about 9, and under about 5 is better.
